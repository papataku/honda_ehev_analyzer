# 0.2.8 次回乗車で取り切るための走行取得

## 目的
運転者がMacを操作しなくても、1回の走行で後解析に必要な診断データをできるだけ多く残す。

## 取得する3層
1. **高優先度**: RPM (010C), 車速 (010D), 冷却水温 (0105), Honda 019A, UDS 222012。
2. **自動状態判定**: 車両が対応していればアクセルペダルPIDを追加高頻度取得。速度/RPM/アクセルから「停止」「EV走行候補」「エンジン走行」「加速」「定速」「減速/回生候補」を自動ラベル化する。
3. **全対応Mode 01巡回**: 0100/0120/0140... のsupport bitmapから車両が対応すると申告したPIDだけを列挙し、高優先度通信の空き時間に1個ずつ巡回する。意味を実装していないPIDもRAW応答は保存する。

## 重要な意味の区別
- 取得する「全データ」は、**Analyzerが送った診断要求への全response CAN IDの応答**である。
- 車内CANバス上を流れる全フレームの受動キャプチャではない。これは将来USB-CAN/CANable等の直接CAN取得で扱う。
- **0.2.9で訂正:** PID 5BはJ1979の `Hybrid/EV Battery Pack Remaining Charge` で、残量（SOC）として扱う。0.2.8時点の「SOCではない」という記述はSession 12後の規格確認で訂正した。
- **0.2.9で更新:** EV走行はエンジンRPM=0等から引き続き候補扱い。一方、PID 9AのHV電流/電力を利用できるため、減速中にHV電力が負なら回生を実測確認できる。

## 通信負荷
前回実車ログのKW905は1要求あたりおよそ120 ms級だった。全PIDを高頻度で問い合わせるとアダプタを飽和させ、重要な速度/RPM/Honda RAWを失うため、priority schedulerを採用する。
- RPM/車速: 2 Hzを維持
- 019A: 約1.25 Hz
- 222012: 0.4 Hz
- アクセル: 対応時 約0.75 Hz
- その他の対応PID: 2秒ごとに1 PIDを巡回
- 遅延時はcatch-up burstを作らず、次周期へ進む

## 運転中の操作
不要。ライブ取得開始後はMacを触らない。助手席の手動マーカーは補足用であり必須ではない。

## 走行後にできる解析
- AUTO_STATEイベントから状態区間を自動抽出
- response CAN ID × PID/019A/222012 × 状態で変化量を比較
- EV候補区間でRPM=0のまま変化するfieldをモーター系候補として抽出
- 加速/減速・回生候補との符号・勾配相関からHV電力候補を抽出
- 長時間ゆっくり変化するfieldをSOC候補として抽出
- 標準PID 5BをHVバッテリーSOCとして時系列比較
