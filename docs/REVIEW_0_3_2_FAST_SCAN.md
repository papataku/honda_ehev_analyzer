# 0.3.2 高速DID探索レビュー

## 車載通信担当
- ELM327はコマンドを直列実行するため、10 req/sを達成するには平均round-trip 100 ms未満が必要。
- Session 14の通常設定は平均約121 msであり、sleepだけを削っても約8.3 req/sが上限。
- 高速探索中だけATAT2/ATST0Fを適用し、終了時に必ず標準設定へ戻す。
- promptを待たずに次コマンドを送るパイプライン化は行わない。

## 安全担当
- 0x22 read-only限定、停車・Pレンジ、定期車速確認を維持。
- 速度向上のため車速監視を削らない。
- timeout/NO DATAをterminal扱いしないため、高速設定によるfalse negativeを永久確定しない。

## データ解析担当
- 既知0x2012帯を先行し、Positive pipelineの健全性を早期検証できる。
- 全範囲は後段で必ず埋めるため探索Coverageは低下しない。

## 初心者UI担当
- 「10 req/s」は目標値であり保証値ではないことを画面へ明記。
- 実効req/sと残り時間を表示し、「遅い=故障」と誤解しにくくした。
