# 0.3.2 DID Discovery 高速化

Session 14の実車ログを基にDID探索を高速化した。

## Session 14で確認した事実

- 2 req/sと3 req/sで実車探索は正常動作した。
- DID要求の実測レイテンシは中央値約120 ms、平均約121 ms。
- ELM通常タイミングのままでは、直列要求の物理上限は平均値ベースで約8.3 req/s。
- 数値順探索では5分程度では0x2012まで到達できなかった。

## 変更

- DID探索の既定値を目標10 req/sへ変更。
- 8 req/s以上では探索中のみ `ATAT2` + `ATST0F` を使用。
  - Adaptive Timingをより積極的にする。
  - ELMの最大待ち時間を約60 msへ短縮する。
- 探索終了・停止・例外時には `ATAT1` + `ATST32` を復元。
- 高速設定がKW905で受理されない場合は通常設定へフォールバック。
- NO DATA / timeoutは従来どおり「確認済み」にしないため、高速設定で遅い応答を逃しても後日再試行できる。
- 実効req/sと残り時間の実測推定を画面表示。
- 全範囲探索時は既知DID 0x2012を含む0x2000–0x20FFを先に探索し、その後で残り範囲を埋める。全範囲Coverageは変えない。

## 注意

10 req/sは送信目標値であり、ELM/BLE/ECUのround-tripが100 msを超える場合は実効値が10を下回る。コマンドを重ねて送ることはせず、常にELM prompt `>`を受信してから次の要求へ進む。
