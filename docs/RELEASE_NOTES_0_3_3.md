# 0.3.3 適応優先DID探索

Session 14とユーザーレビューを基に、DID探索順を単純な昇順から適応優先方式へ変更した。

## 探索順

1. 既知のRP8応答DID 0x2012を含む `0x2000-0x20FF` を先行確認。
2. 全範囲を `0x0000-0x0FFF` ... `0xF000-0xFFFF` の16領域へ分割し、各領域の先頭数DIDを粗探索。
3. 反応密度が高い領域から、各 `0x100` ページの先頭/中央を代表探索。
4. Positive response、またはNRC 0x31以外の条件依存応答があったページは、その場で256 DIDを優先深掘り。
5. 最後に未探索DIDを全て埋める。

代表探索が無反応でも領域は除外しない。優先順位だけを変更し、指定範囲の完全Coverageを維持する。

## 再開

過去セッションのPositive DIDをpriority hintとして再利用する。アプリ終了後・別日の再開でも、過去にPositiveが見つかったsector/pageを先に調べる。

## 高速探索

0.3.2の高速化を継承する。既定は目標10 req/s。8 req/s以上では探索中のみ `ATAT2 + ATST0F` を使用し、終了時に `ATAT1 + ATST32` へ復元する。

10 req/sは目標値であり、ELM/BLE/ECUの実round-tripが100 ms以上なら実効速度は低下する。ELM promptを待たずにコマンドを重ねることはしない。
